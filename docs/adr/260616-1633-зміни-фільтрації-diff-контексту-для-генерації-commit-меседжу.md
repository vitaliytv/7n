## ADR зміни фільтрації diff-контексту для генерації commit-меседжу

## Context and Problem Statement
Команда `npx @7n/n@latest push` зависала через те, що `.n-cursor/llm-trace.jsonl` (~5.4 MB) не виключався з diff-контексту і при алфавітному сортуванні файлів потрапляв першим, заповнюючи весь байтовий бюджет шумом до того, як будь-який корисний код доходив до LLM. Окрім цього, стара стеля `head -c N7COMMIT_MAX_DIFF_BYTES` брала перші N байт усього diff, тобто один великий файл міг повністю витіснити решту.

## Considered Options
* Додати `.n-cursor/**` та `**/*.jsonl` до дефолтного масиву виключень і зменшити константу `N7COMMIT_MAX_DIFF_BYTES`
* **Рівномірний per-file байт-бюджет** (`N7COMMIT_MAX_FILE_BYTES`) із обрізанням кожного файла окремо + маркером обрізання
* Інші варіанти в transcript не обговорювалися.

## Decision Outcome
Chosen option: "Додати виключення `.n-cursor/**`/`**/*.jsonl` **та** per-file байт-бюджет", because обидві правки разом усувають два незалежних класи проблеми: нові шумні шляхи, що не входили до дефолтного `noise`-масиву, і крихкість сумарної байтової стелі, яка давала першому великому файлу необмежену квоту.

### Consequences
* Good, because diff-контекст для репозиторію `nitra/ai` зменшився з ~5.44 MB до ~3.3 KB (~1600×), що гарантує швидку відповідь LLM.
* Good, because per-file бюджет забезпечує рівномірне представлення всіх змінених файлів: синтетичний тест підтвердив, що `aaa_big.txt` (280 KB diff) обрізається до ~16 KB, а три малі файли `zzz_*.js` залишаються в контексті повністю.
