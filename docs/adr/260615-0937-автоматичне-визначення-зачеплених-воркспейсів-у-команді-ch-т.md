## ADR Автоматичне визначення зачеплених воркспейсів у команді `ch` та видалення прапора `--ws`

## Context and Problem Statement

Команда `npx @7n/n ch` вимагала явної передачі `--ws <назва>`, щоб визначити, у який воркспейс писати change-файл. При виклику з кореня монорепо без `--ws` файл завжди потрапляв у кореневий `.changes/` — навіть якщо всі змінені файли знаходилися у воркспейсі `npm/`. Користувач повинен був вручну знати, де лежать змінені файли.

## Considered Options

* Зберегти `--ws` як обов'язковий або опційний прапор (попередня поведінка).
* Автоматично визначати зачеплені воркспейси за виходом `git status` і писати окремий change-файл у кожен з них, видаливши `--ws` повністю.

## Decision Outcome

Chosen option: "Автоматичне визначення воркспейсів через `git status`, видалення `--ws`", because користувач явно зазначив, що `ch` має бути «більш розумним» і аналізувати зміни по воркспейсах окремо без ручного вказування.

### Consequences

* Good, because при змінах у двох воркспейсах (`<корінь>` і `npm`) команда автоматично створює два окремих change-файли — підтверджено живим запуском: `"📦 Зачеплені воркспейси: <корінь>, npm"` → два виклики канону з коректним `cwd=repoRoot`.
* Bad, because transcript не містить підтверджених негативних наслідків.

## More Information

* Реалізація в `npm/ch.js`: нові функції `parsePorcelainZ`, `resolveWorkspaces`, `groupByWorkspace`, `affectedWorkspaces`.
* Алгоритм групування: `git status --porcelain=v1 -z` → розбір через `parsePorcelainZ` → кожен шлях зіставляється з найдовшим воркспейс-префіксом (з кореневого `package.json`, поле `workspaces`); незіставлені файли → `.` (корінь).
* `buildChangeArgs(partial, message, ws)` тепер приймає `ws` окремим параметром; виклик канону: `spawn('npx', ['@nitra/cursor', ...args], { cwd: repoRoot })`.
* Тести: `npm/tests/ch.test.mjs` — 23 тести, 100% зелені після рефакторингу.
* Пакет опублікований як `@7n/n@0.10.0` — GA workflow `npm-publish` завершився успішно.

## ADR Опційний `--message` з генерацією опису через `omlx` окремо для кожного воркспейса

## Context and Problem Statement

Після автоматичного визначення воркспейсів прапор `--message` залишався обов'язковим і спільним для всіх зачеплених воркспейсів. Користувач запросив зробити `--message` опційним, а при його відсутності — генерувати окремий контекстуальний опис для кожного воркспейса на основі його diff.

## Considered Options

* Один спільний згенерований опис для всіх воркспейсів.
* Per-workspace генерація: окремий opml-запит на кожен воркспейс з його власним diff-контекстом.

## Decision Outcome

Chosen option: "Per-workspace генерація через `omlx` з diff-контекстом кожного воркспейса", because користувач прямо зазначив «проаналізує зміни по воркспейсам окремо».

### Consequences

* Good, because живий запуск згенерував два різних доречних описи: `"<корінь>: Видалено багато ADR, оновлено ADR про worktree та портабельний виклик n-cursor release"` і `"npm: Автоматичне визначення воркспейсів та генерація опису змін через omlx"` — без ручного введення.
* Good, because якщо `--message` передано вручну — `omlx` не викликається взагалі (детермінована, швидка поведінка).
* Bad, because transcript не містить підтверджених негативних наслідків.

## More Information

* Реалізація в `npm/ch.js`: `workspaceDiffContext(repoRoot, ws, files)` — збирає `git diff --name-status` + `git diff HEAD` для файлів воркспейса + вміст untracked-файлів, обрізає до `MAX_DIFF_LINES=800`; `buildGenMessages(ws, context)` — chat-промпт (одним рядком ≤72 символи, без emoji/префіксів/лапок); `cleanGeneratedMessage(out)` — чистить вихід моделі до одного рядка (прибирає fences, лапки, кулі, крапки в кінці); `defaultGenerator()` — лінива одноразова ініціалізація `loadOmlxConfig` + `ensureModel`, далі diff→`omlxChat`→clean.
* Залежність: `./omlx.mjs` — той самий OpenAI-сумісний MLX-клієнт (`omlxChat`, `loadOmlxConfig`, `ensureModel`), що використовується в `merge.js` і `push.js`; env-змінні реюзуються (`N7MERGE_OMLX_URL`, `N7MERGE_OMLX_KEY`, `N7MERGE_OMLX_MODEL` тощо) — окремих `N7CH_*` не вводилося.
* Промпт задає обмеження: українська мова, один рядок, без emoji, без конвенційних префіксів (`feat:`, `fix:` тощо), без лапок — `cleanGeneratedMessage` підстраховує виконання цих вимог.
* Тести: `npm/tests/ch.test.mjs` — покрито `cleanGeneratedMessage`, `buildGenMessages`, `runCh` без `--message` (omlx інжектується через DI, мережі не торкаються).
