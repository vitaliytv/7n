## ADR Авто-визначення воркспейсів для `@7n/n ch`

## Context and Problem Statement
Команда `npx @7n/n ch` раніше вимагала явного прапора `--ws`, щоб вказати, у який воркспейс монорепо покласти change-файл. Якщо користувач викликав команду з кореня, а змінені файли лежали в `npm/`, change-файл потрапляв у кореневий `.changes/` замість `npm/.changes/`. Потрібен автоматичний механізм, що сам визначає зачеплені воркспейси.

## Considered Options
* Залишити ручний `--ws` (попередня поведінка)
* Авто-детекція воркспейсів через `git status` + `package.json`

## Decision Outcome
Chosen option: "Авто-детекція воркспейсів через `git status` + `package.json`", because користувач явно вимагав прибрати `--ws` і щоб команда сама визначала воркспейси зі змін, створюючи окремий change-файл для кожного зачепленого воркспейса.

### Consequences
* Good, because команда не вимагає ручного вказання `--ws`; при змінах у кількох воркспейсах автоматично створюються відповідні `change`-записи в кожному `.changes/`.
* Bad, because логіка залежить від `git status` — у fresh clone без staged/unstaged змін команда не визначить жодного воркспейса (буде no-op). Transcript не містить підтверджених негативних наслідків для production-сценаріїв.
