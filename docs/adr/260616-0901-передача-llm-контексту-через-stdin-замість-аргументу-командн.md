## ADR Передача LLM-контексту через stdin замість аргументу командного рядка

## Context and Problem Statement
`npx @7n/n push` завершується з помилкою `argument list too long` при виклику LLM-агентів (`pi -p`, `claude -p`, `cursor-agent -p`) у функції `_n7push_gen_message` (`npm/push.js:64`). Diff-контекст для генерації commit-меседжу займає ~3.78 МБ (3 787 808 символів), тоді як системний ліміт `ARG_MAX` на цій платформі — 1 048 576 байт (~1 МБ). Всі три fallback-агенти повернули `rc=127` через той самий OS-обмеження.

## Considered Options
* Передача prompt/контексту як аргументу командного рядка (поточна реалізація в `_n7push_gen_message`)
* Передача через stdin (pipe або heredoc) або через існуючий temp-файл (`ctx=/var/folders/.../tmp.eqLaPvjQ46`)

Інших варіантів в transcript не обговорювалося.

## Decision Outcome
Chosen option: "Передача через stdin або temp-файл", because поточний спосіб (аргумент CLI) стабільно падає при diff-контексті понад ~1 МБ — що підтверджується ARG_MAX=1048576 і фактичним розміром промпту ~3.78 МБ. Temp-файл (`ctx=…`) вже створюється (`5 444 777 б, 1326 рядків`), але його вміст все одно передається рядком в args замість redirect-у.

### Consequences
* Good, because усунення передачі великого промпту через args вирішує `argument list too long` незалежно від розміру diff.
* Bad, because transcript не містить підтверджених негативних наслідків.
