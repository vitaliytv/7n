# Перевірка зовнішніх інструментів та API перед генерацією команд

**Status:** Accepted
**Date:** 2026-06-10

## Context and Problem Statement

Під час консультації з omlx та mlx-lm асистент написав неіснуючу команду `omlx run mlx-community/gemma-4-2B-it-4bit` — за аналогією з `ollama run`, не перевіривши реальний CLI omlx. Це призвело до поширення некоректної інформації. Наприкінці сесії користувач явно вказав на помилку і попросив переглянути правила.

## Considered Options

* Генерувати команди за аналогією з подібними інструментами (ollama, docker тощо)
* Перевірити README / формулу / API документацію перед написанням команди

## Decision Outcome

Chosen option: "Перевірити README / формулу / API документацію перед написанням команди", because правила проєкту (`CLAUDE.md`) забороняють генерувати або вгадувати URLs та команди без впевненості в їх коректності; README omlx явно описує `omlx start` / `omlx serve` як єдині команди запуску, що підтверджується текстом формули `Formula/omlx.rb` та `pyproject.toml`.

### Consequences

* Good, because команди відповідатимуть реальному CLI інструменту і не вводитимуть користувача в оману.
* Bad, because додаткові виклики `WebFetch` / `gh api` збільшують час відповіді перед наданням рекомендації.

## More Information

- README omlx (через `gh api repos/jundot/omlx/contents/README.md`): `omlx start`, `omlx serve --model-dir ~/models` — єдині задокументовані команди запуску.
- Формула `Formula/omlx.rb`: ресурс `mlx-lm` зафіксований на `v0.31.3`.
- Правило з `CLAUDE.md`: *"You must NEVER generate or guess URLs for the user unless you are confident..."*
- Помилкова команда: `omlx run mlx-community/gemma-4-2B-it-4bit` (аналогія з `ollama run`, не існує в CLI omlx).
