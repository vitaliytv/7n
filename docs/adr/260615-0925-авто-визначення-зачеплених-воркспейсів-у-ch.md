## Considered Options

## Decision Outcome

### Consequences
* Good, because transcript фіксує очікувану користь: один виклик `npx @7n/n ch` без аргументів коректно створює два окремих change-файли (`<корінь>/.changes/…` і `npm/.changes/…`), якщо є зміни в обох місцях.

## ADR `--message` опційний: генерація через omlx per-workspace

## Context and Problem Statement
Після авто-визначення воркспейсів `--message` залишався обов'язковим і єдиним для всіх воркспейсів. Користувач попросив зробити його опційним, а коли він відсутній — генерувати окремий опис для кожного воркспейса через omlx.

## Considered Options
* Генерувати per-workspace опис через omlx (`omlxChat` з diff відповідного воркспейса) за відсутності `--message`
* Інші варіанти в transcript не обговорювалися.

## Decision Outcome
Chosen option: "Генерувати per-workspace опис через omlx за відсутності `--message`", because це є прямою реалізацією ідеї «аналіз змін по воркспейсах окремо», яку сформулював користувач на початку сесії.

### Consequences
* Good, because transcript фіксує очікувану користь: omlx згенерував два різні, змістовні описи з diff кожного воркспейса: `📝 <корінь>: Видалено багато ADR…` і `📝 npm: Автоматичне визначення воркспейсів…`.
* Bad, because transcript не містить підтверджених негативних наслідків.
