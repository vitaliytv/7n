## ADR Авто-визначення зачеплених воркспейсів у команді `ch` та видалення `--ws`

## Context and Problem Statement

Монорепо може мати зміни одночасно в кількох воркспейсах, і тоді користувач мав би викликати `ch` вручну для кожного.

## Considered Options
* Авто-визначення зачеплених воркспейсів через `git status` + `package.json#workspaces` і прибрати `--ws`
* Інші варіанти в transcript не обговорювалися.

## Decision Outcome
Chosen option: "Авто-визначення зачеплених воркспейсів через `git status` + `package.json#workspaces`", because користувач явно сформулював вимогу: «він дивиться де є змінені файли, і якщо вони є в двох різних воркспейсах — робить changes в кожному окремо; прибираємо `--ws` взагалі».

### Consequences

## ADR Опційний `--message` з per-workspace генерацією через omlx

## Context and Problem Statement
Після авто-визначення воркспейсів `--message` залишався єдиним обов'язковим аргументом, але один текст на всі воркспейси не відображав семантику змін у кожному з них окремо. Бажано дати можливість не передавати `--message` взагалі і отримувати аналітичний опис автоматично.

## Considered Options
* Генерація per-workspace описів через `omlx` (локальний OpenAI-сумісний MLX-сервер) на основі `git diff` кожного воркспейса
* Інші варіанти в transcript не обговорювалися.

## Decision Outcome
Chosen option: "Генерація per-workspace описів через `omlx`", because користувач сформулював вимогу: «якщо `--message` не передано — генеруємо його через omlx»; omlx вже використовувався в `npm/omlx.mjs` для merge-резолюції, тому реюз наявного механізму був природним.

* Good, because якщо `--message` задано вручну — `omlx` не викликається взагалі (детерміновано й швидко).
